# START — Нейрокоманда на VPS: с нуля до приложения

Версия комплекта: `0.1.2-preview` (предварительная, независимо не проверена; границы — в `README.md`).

## Что сказать нейрокоманде

Откройте эту папку в VS Code, запустите Claude или Codex и отправьте:

> Прочитай START.md и проведи меня до проверенного рабочего приложения. Продолжай по сохранённому состоянию.

Эта же фраза работает после нового чата, перезапуска VS Code и после перехода в удалённое окно.

## Протокол агента (читай полностью до первого действия)

Ты ведёшь участника по 12 этапам. Правила комплекта — в `CLAUDE.md` / `AGENTS.md` (они идентичны по блоку правил и обязательны). Человек делает покупки, авторизацию, ввод секретов, подтверждения административных действий и проверку интерфейса. Остальное делаешь сам.

### Шаг 0. Проверь комплект
Прочитай `VERSION` и `MANIFEST.sha256`. Сообщи участнику версию и число файлов; диагностика (шаг 2) сверит хеши. При расхождении версии или состава — остановись и скажи, какого файла не хватает; к серверу не переходи.

### Шаг 1. Определи ОС и режим окна
- Ноутбук: **Windows** → `tools/diagnose.ps1`, **macOS** → `tools/diagnose.sh`. Если диагностика сообщила `linux`, вы уже в удалённом окне: перейди к разделу «Удалённое окно».
- Если ОС не определилась, задай один вопрос; не угадывай.

### Шаг 2. Запусти стартовую диагностику (read-only)

Windows:
```
powershell -NoProfile -File tools\diagnose.ps1
```
macOS:
```
bash tools/diagnose.sh
```
Диагностика ничего не меняет. Она пишет только в `state/` и печатает строки `CHECK <id> <STATUS> <value>` и `QUESTION ...`. Статусы: `PASS`, `NOT_FOUND`, `UNKNOWN`, `BLOCKED_BY_LOCAL_PERMISSION`, `NOT_RUN`, `FAIL`.

- Что скрипт не может увидеть (VPN, режим разрешений, выбранный workspace, готовность карты), он спрашивает: задай участнику **один короткий вопрос** и запиши ответ командой `-Answer ключ=значение` (Windows) или `--answer ключ=значение` (macOS). Допустимые ключи и значения — `tools/README.md`.
- `BLOCKED_BY_LOCAL_PERMISSION` — локальный отказ разрешений. Серверные проверки `NOT_RUN`. Не считай это ошибкой SSH/VPS, не обходи отказ: скажи участнику, что именно разрешить разово.

### Шаг 3. Ведись по `state/stages.tsv`
Строка этапа: `этап, статус, метка, источник, дата, код-заметки`. Статусы `PASS` / `PENDING` / `BLOCKED` / `NOT_RUN` / `CLAIMED` (заявлено документами проекта, не проверено). Этапы со статусом `PASS` пропускаются (`SKIP`), остальные, включая `CLAIMED`, выполняются или проверяются (`RUN`). Повторная проверка пройденного этапа допустима только при изменении входных данных (новый хост или ключ, обновление клиента, смена VPN или сети, конкретная ошибка): `-Reset N` / `--reset N`.

PASS записывается командой с обязательными источником и меткой (без них команда отказывает):
- Windows: `powershell -NoProfile -File tools\diagnose.ps1 -Accept 4 -Source ssh-whoami -Evidence L`
- macOS: `bash tools/diagnose.sh --accept 4 --source ssh-whoami --evidence L`

### Шаг 5. Веди карточку и отчёт
- Читаемая карточка: `state/state-card.md` по шаблону `templates/state-card.md` (без секретов, адресов, имён пользователей и абсолютных путей).
- Отчёт продолжения: `state/continuation-report.md` по `templates/continuation-report.md`; обновляй после каждого значимого шага и перед завершением сессии.
- Не требуй от участника пересылки отчётов через GPT. GPT-проводник (если он есть) нужен для объяснений и конкретных блокеров.

## Если комплект лежит внутри существующего VPS-проекта
Так бывает, когда `BOOTSTRAP.md` поставил комплект в подпапку `neuro-lab-vps` проекта участника. Тогда:
- **Проект участника главный.** Его `CLAUDE.md`, `AGENTS.md`, `STATUS` и настройки не заменяются и не правятся комплектом; комплект ведёт только маршрут и состояние в своей подпапке. Параллельный VPS-проект не создаётся.
- Свяжи состояние с проектом одной командой: `-Answer project_link=parent` (macOS: `--answer project_link=parent`). Путь к проекту в состояние не записывается.
- **Подтверждённые этапы проекта — это заявления, а не PASS.** Прочитай документы проекта и для каждого этапа, который они называют выполненным, запиши заявление: `-Claim N -Source project-status`. Затем проверь каждое заявление фактом (read-only проверки, вывод инструментов) или попроси владельца подтвердить его словами и запиши `-Accept N -Source <источник> -Evidence L` или `-Evidence U`. Наличие файла и утверждение модели PASS не дают.
- Принятые этапы дальше пропускаются, заявленные остаются в плане до проверки.

## Если комплект пришёл с GitHub
Основной вход — `BOOTSTRAP.md`: он один раз передаётся нейрокоманде до получения комплекта (найти папку, получить закреплённый выпуск, проверить, прочитать этот файл). ZIP — резервный канал: после ручной распаковки сразу переходи к «Шаг 0».

## Сообщение об ошибке без секретов
`powershell -NoProfile -File tools\diagnose.ps1 -Report` (macOS: `bash tools/diagnose.sh --report`) печатает безопасную сводку: версия, метка ОС, таблица этапов, статусы проверок. К ней человек добавляет номер этапа и что он видел своими словами. Подробнее — `REPORT-A-PROBLEM.md`.

## Удалённое окно (переход из локального в удалённый workspace)

1. Этап 5 завершается, когда окно VS Code показывает удалённый хост, терминал выполняется на сервере, а в удалённой рабочей папке лежит копия комплекта без `state/` и без ключей.
2. Дальше работа идёт **в удалённом окне**: открой в нём эту же копию, расширения Claude/Codex установлены на хосте (этап 7), `START.md` читается там же.
3. Каноническая карточка с этого момента — копия в удалённой папке (`state/` создаётся диагностикой на Linux). Локальная копия `state/` остаётся историей до этапа 5; перенеси в удалённую `state/` только `stages.tsv` и `answers.tsv` (в них нет секретов). Ветка помечена `[?]`: проверяется при независимом прогоне.
4. В Linux-окне диагностика (`bash tools/diagnose.sh`) определяет ОС как `linux`; проверки ноутбука (VS Code, локальный ssh) в нём не применимы и получают `NOT_RUN`.

## Места выполнения
`AGENT` — делаешь сам. `HUMAN-LOCAL-TERMINAL` — человек в терминале ноутбука. `HUMAN-REMOTE-TERMINAL` — человек в терминале удалённого окна. `PROVIDER-PANEL` — сайт/консоль провайдера (при недоступности через VPN — другое устройство). `GPT` — чат-проводник.

Терминал: Windows — меню «Терминал → Создать терминал» в VS Code (при скрытом меню — «…»); macOS — то же меню или `Ctrl+\``. Первый вход по паролю делает человек сам; пароль вставляется один раз, символы при вводе не показываются.

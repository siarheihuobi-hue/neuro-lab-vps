# Neuro-lab · Нейрокоманда на VPS: с нуля до приложения

Версия `0.1.2-preview`. **Это предварительная версия (preview).** Реальные macOS и Linux не проверены, полный независимый маршрут на чистом ноутбуке и чистом сервере другим человеком не пройден (подробнее ниже). Репозиторий: `https://github.com/siarheihuobi-hue/neuro-lab-vps`. Лицензия кода: Apache-2.0 (`LICENSE`). Условия Neuro-lab пока не утверждены.

## Результат
Цель маршрута — получить **один свой VPS**, на котором работает ваша нейрокоманда в VS Code (Claude и/или Codex), с настроенным доступом по ключу, базовой защитой сервера и работающим демо-приложением, открытым через вкладку Ports. Маршрут из 12 этапов ведёт сама нейрокоманда: она выполняет всё, что может, и останавливается там, где нужны вы (покупка, авторизация, пароль, подтверждение, проверка интерфейса). Сохранённое состояние позволяет остановиться и продолжить позже.

Бесплатный маршрут заканчивается на одном VPS и ничем не ограничен ради платных предложений: второй сервер, оплата и лицензирование здесь не требуются.

## Что нужно заранее
| Что | Зачем | Расходы |
|---|---|---|
| Ноутбук с Windows 11 или macOS и правом установить [VS Code](https://code.visualstudio.com/) | рабочее место | — |
| VPN, который остаётся включённым | без него у части участников не работает сам агент | на вашей стороне |
| Аккаунт Claude и/или Codex | нейрокоманда в VS Code | подписка на движок (тариф выбираете вы) |
| Аккаунт провайдера VPS и способ оплаты | сервер Ubuntu 24.04 | аренда сервера (выбираете провайдера и тариф вы); подходит и уже имеющийся сервер |
| Телефон или второе устройство | панель провайдера, если она недоступна через VPN | — |

Цены не указываются: они зависят от провайдера и подписки. Соблюдение условий провайдеров (VPS, Claude, Codex, VPN) и местного законодательства, в том числе при выборе VPN и способа оплаты, — на вас; комплект правовой корректности не обещает.

## Быстрый старт
1. Откройте VS Code и свою нейрокоманду (Claude или Codex).
2. Отправьте ей одну фразу: «Прочитай `https://raw.githubusercontent.com/siarheihuobi-hue/neuro-lab-vps/v0.1.2-preview/BOOTSTRAP.md` и выполни его» (текст `BOOTSTRAP.md` можно и просто вставить в чат). Если выпуск `v0.1.2-preview` ещё не опубликован, установка остановится с сообщением `RELEASE_NOT_FOUND` и ничего не изменит.
3. Нейрокоманда определит ОС и состояние, найдёт уже установленный комплект или ваш существующий VPS-проект (по содержимому, а не по имени; только в текущем workspace и рядом, диск целиком не сканируется) и продолжит в нём; если у вас есть VPS-проект без комплекта, после вашего подтверждения комплект ляжет в отдельную подпапку `neuro-lab-vps` этого проекта, не заменяя его `CLAUDE.md`, `AGENTS.md`, `STATUS` и настройки, а этапы, которые ваши документы называют выполненными, будут сначала проверены, а не приняты на веру. Новую папку нейрокоманда создаёт лишь при отсутствии подходящей и никогда не пишет в папку проекта без вашего подтверждения. Затем получит закреплённый выпуск, проверит целостность, прочитает `START.md` и начнёт с диагностики. Дальше отвечайте на её короткие вопросы и выполняйте только то, что она назвала действием человека.

Не нужен ChatGPT-посредник: он необязателен и годится лишь для объяснений и конкретных блокеров. Резервный канал: ZIP из раздела выпусков (`neurokomanda-vps-kit-<версия>.zip` и `.sha256` рядом); после ручной распаковки откройте папку в VS Code и отправьте: «Прочитай START.md и проведи меня до проверенного рабочего приложения. Продолжай по сохранённому состоянию».

## С нуля или продолжить
- **С нуля:** этапы 1–12 подряд.
- **Продолжить:** после перерыва, нового чата или перезапуска повторите ту же фразу. Нейрокоманда читает `state/stages.tsv` и `state/continuation-report.md`, пропускает этапы с принятым доказательством и продолжает с первого без PASS. Готовые интервью и карта не повторяются. Повторный запуск не стирает состояние и ваши изменения.

## Поддерживаемые и непроверенные среды
| Среда | Статус |
|---|---|
| Ноутбук Windows 11, Windows PowerShell 5.1, диагностика | прогнана на одном ноутбуке во временной среде |
| Ноутбук macOS | **не проверен**: скрипт прогонялся в Git Bash с подменой метки ОС (имитация, не тест на macOS) |
| Сервер Ubuntu 24.04 | подтверждён на одном эталонном сервере со слов владельца; **другие ОС не проверены** |
| UFW и SSH hardening | выполнены один раз на эталонном сервере; другим человеком не повторялись |
| Claude и Codex в VS Code (Remote-SSH) | результаты эталонного контура (отчёты владельца); независимо не воспроизведены |
| Полный маршрут на чистом ноутбуке и чистом сервере | **не пройден** |

## Границы безопасности и автоматизации
- Пароли, приватные ключи и токены вводит только человек, локально; в комплект, чат, отчёты и телеметрию они не попадают.
- Claude работает в режиме Manual перед административными операциями, Codex со штатными подтверждениями. Bypass и широкие постоянные разрешения не используются.
- Серверные изменения идут только по процедурам: резервная копия, автоматический откат до изменения, проверка новым входом. Постоянного root-помощника и NOPASSWD нет.
- Демо слушает только `127.0.0.1` и открывается через Ports; данные демо хранятся в `localStorage` браузера, не на сервере.
- Содержимое, которое читает агент, передаётся провайдеру ИИ по его условиям; данные третьих лиц переносите на зарубежный сервер только если вправе это делать.
- Не входит и не обещается: работа 24/7, отсутствие блокировок, юридическая корректность обработки персональных данных, запуск skills, внешний sync, именованные агенты Claude, число ролей больше восьми, админ-панель, установщик, телеметрия по сети (есть только схема и локальные события диагностики).

## Как сообщить об ошибке без секретов
Выполните `powershell -NoProfile -File tools\diagnose.ps1 -Report` (macOS: `bash tools/diagnose.sh --report`) и приложите вывод вместе с номером этапа и описанием своими словами. Не присылайте пароли, ключи, IP-адреса, имена пользователей, пути и скриншоты без закрашивания. Подробнее — `REPORT-A-PROBLEM.md`.

## Что в комплекте
| Путь | Что |
|---|---|
| `BOOTSTRAP.md` | вход для GitHub: передаётся нейрокоманде один раз; блоки обнаружения комплекта и проекта и установки |
| `START.md`, `CLAUDE.md`, `AGENTS.md` | точка входа и общие правила для Claude и Codex |
| `stages/` | сценарии этапов 0–12 |
| `templates/` | карточка состояния и отчёт продолжения |
| `tools/` | стартовая диагностика (read-only) |
| `procedures/` | UFW, SSH hardening, preflight, разбор SSH-ошибок, аудит и перенос команды |
| `team-skeleton/` | очищенный каркас команды (8 ролей) и адаптеры Codex |
| `demo/` | готовое демо-приложение, происхождение, проверки |
| `telemetry/` | закрытая схема локальных событий |

| `VERSION`, `MANIFEST.sha256`, `manifest.json` | версия и хеши файлов |

Состояние участника (`state/`) создаётся на вашем ноутбуке, не входит в выпуск и не попадает в Git.

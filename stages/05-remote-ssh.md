# Этап 5. Microsoft Remote-SSH и переход в удалённый workspace

**Вход:** этап 4 PASS и серверная проверка `PREFLIGHT` (read-only, `procedures/preflight/`, после первого доступа). Используется только официальное расширение Microsoft Remote-SSH ([документация](https://code.visualstudio.com/docs/remote/ssh)). Самодельные обходы (отсоединённые SSH-сессии, повышение прав как приём) не входят в комплект.

| Место | Действие |
|---|---|
| `AGENT` | **сам** добавить (или исправить) блок хоста в **пользовательский** SSH config: проверить, не лежит ли файл как `config.txt`, существующие блоки других хостов сохранить, записать атомарно (временный файл → проверка разбора SSH → замена), указать проектный ключ и проектный `known_hosts`; адрес в комплект и отчёты не попадает; после подключения проверить `whoami` и `hostname` |
| `HUMAN` | в VS Code выбрать хост (Remote-SSH: Connect to Host), открыть рабочую папку на сервере, открыть терминал и убедиться, что он на сервере |

Файл SSH-config не переписывается целиком и не заменяется «наугад»: перед записью агент читает его, делает копию рядом (без секретов), добавляет свой блок и проверяет, что алиас разбирается клиентом SSH (`ssh -G <алиас>` показывает нужные параметры без подключения). Ошибочное имя `config.txt` исправляет агент после проверки.

## Переход из локального окна в удалённый workspace
1. Агент создаёт на сервере рабочую папку (например, `~/workshop`) и копирует туда комплект **без** `state/`, ключей и `known_hosts` (`scp`/`rsync` по проектному ключу; подтверждение административной операции — Manual). Способ копирования проверен только на одном контуре `[?]`.
2. Человек открывает эту папку в удалённом окне VS Code.
3. **Одна каноническая карточка.** С момента перехода состояние ведёт удалённая копия: агент переносит в удалённую `state/` файлы `stages.tsv`, `facts.tsv`, `meta.tsv`, `answers.tsv` (секретов в них нет; поколение сервера сохраняется) и дописывает в отчёт продолжения «окно: удалённое; каноническая карточка: удалённая». Локальная `state/` остаётся только историей и не редактируется; новые факты пишутся в удалённую. Передача проверена на одном контуре `[?]`.
4. Дальше START.md читается в удалённом окне; диагностика определяет ОС как `linux`, и место подтверждается индикатором SSH или ответом (`exec_place`).

**PASS:** окно VS Code показывает удалённый хост, `whoami` — обычный пользователь, открыта удалённая рабочая папка с комплектом, `PREFLIGHT` записан. `-Fact PREFLIGHT=PASS -Source preflight -Evidence L`, затем `-Accept 5 -Source remote-window -Evidence LU` (L — `whoami` агента, U — человек видит окно).

**Ошибка:** подключение не стартует → Output расширения Remote-SSH и один точечный разбор по тексту ошибки; VPN остаётся включённым. Причину исторического локального `Permission denied` не обобщать: она не установлена; повышение прав и маршрут `/32` не являются решением для участников.

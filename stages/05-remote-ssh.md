# Этап 5. Microsoft Remote-SSH и переход в удалённый workspace

**Вход:** этап 4 PASS. Используется только официальное расширение Microsoft Remote-SSH ([документация](https://code.visualstudio.com/docs/remote/ssh)). Самодельные обходы (отсоединённые SSH-сессии, повышение прав как приём) не входят в комплект.

| Место | Действие |
|---|---|
| `AGENT` | добавить запись хоста в **пользовательский** SSH config (адрес в комплект и отчёты не попадает), указать проектный ключ и проектный `known_hosts`; после подключения проверить `whoami` и `hostname` |
| `HUMAN` | в VS Code выбрать хост (Remote-SSH: Connect to Host), открыть рабочую папку на сервере, открыть терминал и убедиться, что он на сервере |

## Переход из локального окна в удалённый workspace
1. Агент создаёт на сервере рабочую папку (например, `~/workshop`) и копирует туда комплект **без** `state/`, ключей и `known_hosts` (`scp`/`rsync` по проектному ключу; подтверждение административной операции — Manual). Способ копирования проверен только на одном контуре `[?]`.
2. Человек открывает эту папку в удалённом окне VS Code.
3. Агент переносит в удалённую `state/` только `stages.tsv` и `answers.tsv` (в них нет секретов) и дописывает в отчёт продолжения «окно: удалённое».
4. Дальше START.md читается в удалённом окне; в нём диагностика определяет ОС как `linux` и проверки ноутбука получают `NOT_RUN`.

**PASS:** окно VS Code показывает удалённый хост, `whoami` — обычный пользователь, открыта удалённая рабочая папка с комплектом. `-Accept 5 -Source remote-window -Evidence LU` (L — `whoami` агента, U — человек видит окно).

**Ошибка:** подключение не стартует → Output расширения Remote-SSH и один точечный разбор по тексту ошибки; VPN остаётся включённым. Причину исторического локального `Permission denied` не обобщать: она не установлена; повышение прав и маршрут `/32` не являются решением для участников.

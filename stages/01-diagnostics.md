# Этап 1. Диагностика и карточка состояния

**Вход:** любой (A — с нуля, B — продолжение после короткой диагностики).

| Место | Действие |
|---|---|
| `AGENT` | проверить версию и состав комплекта по `MANIFEST.sha256`; запустить `tools/diagnose.ps1` (Windows) или `tools/diagnose.sh` (macOS); прочитать `state/stages.tsv` |
| `HUMAN` | ответить на короткие вопросы (VPN, режим разрешений, выбранная папка, готовность карты); показать готовые интервью и карту, если они есть |

## Порядок
1. Определи ОС по результату диагностики (не угадывай). Команды, пути и горячие клавиши дальше только для неё.
2. Запусти диагностику. Для каждой строки `QUESTION` задай один короткий вопрос и запиши ответ (`-Answer ключ=значение` / `--answer ключ=значение`).
3. Для `BLOCKED_BY_LOCAL_PERMISSION` назови одну точную разовую операцию, которую должен подтвердить человек; серверные проверки отметь `NOT_RUN`.
4. Прочитай `STAGE_PLAN`: `SKIP` — у этапа есть принятое доказательство, `RUN` — нужно выполнять. Повторный аудит этапа допустим только при изменении входных данных (новый хост или ключ, обновление клиента, смена VPN или сети, конкретная ошибка): `-Reset N`.
5. Готовое интервью и карта: если `state/map.md` есть и входные данные не менялись, **не задавай вопросы заново**. Идентификатор и дату карты запиши в карточку один раз.
6. Создай `state/state-card.md` по `templates/state-card.md` и `state/continuation-report.md` по `templates/continuation-report.md`.

**PASS (ставит скрипт):** определена ОС, версия и состав комплекта совпали с манифестом, `state/stages.tsv` создан, у каждого этапа есть статус и источник. Секретов, адреса и имён пользователей в состоянии нет.

**Ошибка:** проверка не выполнилась → строка остаётся `UNKNOWN`/`NOT_RUN`, слова человека записываются как `[U]`; глубокого расследования нет.

Граница: диагностика не видит VPN, режим разрешений агента, расширения на SSH-хосте и выбор папки; это вопросы человеку, а не факты проверки.

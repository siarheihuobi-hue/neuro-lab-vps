# Этап 2. Ноутбук, VS Code, VPN

**Вход:** нет подтверждённых VS Code, клиента SSH или режима VPN (по `diagnostics.tsv`).

| Место | Действие |
|---|---|
| `HUMAN-LOCAL` | установить VS Code (официальный сайт); **включить VPN и оставить включённым**; при подсказке установить расширение Microsoft Remote-SSH |
| `AGENT` | проверить версии (`code --version`, `ssh -V`) и расширение `ms-vscode-remote.remote-ssh`; создать рабочую папку проекта; записать в карточку «VPN включён» со слов человека `[U]` |

## Правила
- VPN на рабочем ноутбуке **не отключается** (без него у части участников не работает сам агент). Настройки VPN не менять и не расследовать.
- Панель провайдера может быть недоступна через VPN: открывать её с телефона или другого устройства. Это не ошибка SSH.
- Три разных соединения: панель/сайт провайдера, SSH к серверу, соединения движков с сервисами. Недоступность одного не переносится на другие.
- Для чужого VPN достаточно короткой проверки на этапе 5 (Remote-SSH доходит до хоста, `whoami` отвечает). Диагностика VPN — только при конкретном отказе, один раз.
- Тексты сообщений и пути зависят от ОС: Windows — `Ctrl+Shift+P`, Terminal → New Terminal; macOS — `Cmd+Shift+P`. Ветка macOS `[?]`.

**PASS (ставит скрипт при выполнении всех условий):** `vscode` и `ssh_client` PASS по проверке, ответ `vpn=on` от человека (метка `LU`). Если скрипт не нашёл `code` в PATH: человек читает версию в About, агент записывает `-Accept 2 -Source human-version -Evidence U`.

**Ошибка:** конфликт версий или расширений → один раз смотреть Output расширения. Прецедент: ошибка `PendingMigrationError` относилась к встроенному расширению VS Code, а не к Remote-SSH. VPN-конфигурацию не менять.

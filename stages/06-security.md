# Этап 6. Безопасность сервера: UFW и SSH hardening

Серверные изменения идут **только по процедурам**: `procedures/ufw.md` и `procedures/ssh-hardening.md`. Они доказаны один раз на эталонном контуре (Ubuntu 24.04, OpenSSH 9.6, 2026-10-05) и **не проверены независимо** `[?]`.

**Вход:** key-auth под обычным пользователем работает (этап 4, 5); есть **управляемый административный канал** (не «открытое окно», а канал, в который агент может отправить команду и получить вывод).

## Порядок
1. UFW (`procedures/ufw.md`): фактический порт SSH и существующие правила → разрешён только SSH → резервная копия → автооткат до включения → включение → новый вход обычного пользователя → отмена отката.
2. SSH hardening (`procedures/ssh-hardening.md`): порядок директив и эффективные значения на **конкретном сервере** → резервная копия → автооткат и завершение, взведённые до изменения → изменение → `sshd -t` и эффективная конфигурация до перезагрузки сервиса → новый вход → отрицательный тест root → Remote-SSH → завершение под блокировкой.
3. Каждая административная операция: объявить действие до выполнения, получить подтверждение Manual (Claude) или штатное подтверждение (Codex).

## Границы
- Не открывать 443, демо-порты и любые другие порты без отдельного решения человека. Rate-limit, Fail2ban, port knocking в комплект не входят.
- Не создавать постоянный root-helper, не включать NOPASSWD. После закрытия root-входа административные операции — обычный пользователь и пароль sudo, вводимый человеком (или консоль провайдера, если она проверена).
- Файрвол провайдера (на стороне панели) и консоль провайдера как независимый канал восстановления не проверяются комплектом `[?]`: человек сообщает, что есть; запись метка `U`.
- Отказ локальных разрешений — `BLOCKED_BY_LOCAL_PERMISSION`, серверная проверка `NOT_RUN`.
- Если управляемого канала нет, hardening не начинается: зафиксируй блокер «нет управляемого канала» и вернись к этапу 7–12 без hardening, прямо сказав участнику, что безопасность сервера не завершена.

**PASS:** каждая из процедур выполнена полностью, её проверки пройдены, итоговые эффективные значения записаны; временные механизмы удалены, резервная копия сохранена. Отдельно `-Accept 6` ставится только если завершены **обе** процедуры; если выполнена одна, запиши её в карточку и оставь этап `PENDING`.

**Ошибка:** любой сбой нового входа — не отменять откат; ждать автооткат; проверить восстановление доступа.

Статус референса: UFW PASS и SSH hardening PASS на одном контуре, независимого прогона нет.

# Этап 4. Первоначальная подготовка доступа

Обязательный явный этап **до** Remote-SSH. Три проверки A, B, C независимы: «ключ создан» не засчитывается как «ключ установлен» или «вход по ключу работает».

**Вход:** есть сервер и первичный доступ (пароль root от провайдера); проектного ключа или обычного пользователя нет.

## Подсказки до первого ввода пароля (показать целиком)
- Терминал: VS Code → меню «Терминал» (при скрытом меню через «…»); для ОС участника.
- Пароль при вводе не показывается — это нормально. Вставить **один раз** и нажать Enter; несколько вставок дают неверный пароль.
- После одной неудачи — стоп, повтор запрещён до изменения факта (другое устройство, новый пароль).
- Пароль, IP и ключи не отправлять в чат; на скриншоте скрыть. Раскрытый пароль меняет владелец.
- Первый вход по паролю делает **человек** (`HUMAN-LOCAL-TERMINAL`).

## Шаги
| № | Место | Действие | Доказательство |
|---|---|---|---|
| 4.0 | `HUMAN-LOCAL-TERMINAL` + `PROVIDER-PANEL` | первое подключение; отпечаток хоста (ED25519), показанный клиентом, сверяется с независимым каналом (панель или консоль провайдера) и записывается в проектный `known_hosts` с `StrictHostKeyChecking=ask` | отпечатки совпали (человек подтвердил) `[U]` |
| 4.A | `AGENT` | проектный ключ ED25519 создан на ноутбуке (приватный ключ остаётся на ноутбуке); проверить, что публичная часть читается и права файла ключа корректны | `ssh-keygen` читает ключ, отпечаток публичной части записан в карточку (отпечаток — не секрет) |
| 4.B | `HUMAN-LOCAL-TERMINAL` (пароль) | на сервере создан **обычный пользователь**, его `authorized_keys` содержит ровно этот публичный ключ; права `.ssh` 700 и `authorized_keys` 600 | со стороны сервера отпечаток ключа в `authorized_keys` совпал |
| 4.C | `AGENT` | **отдельный** вход по ключу под обычным пользователем: `BatchMode=yes`, пароль и keyboard-interactive отключены, строгая проверка хоста | `whoami` вернул обычного пользователя, код выхода 0, пароль не запрашивался |

Права обычного пользователя: членство в группе `sudo`; **passwordless sudo не настраивается** (NOPASSWD запрещён). Для административных операций пароль sudo вводит человек.

## Правила и прецеденты
- Если проектный ключ отвергнут: **одна** диагностика «почему отклонён ключ» — права и владелец файла приватного ключа на ноутбуке (Windows OpenSSH отвергает слишком открытые права: `bad permissions`), установленный публичный ключ, права `authorized_keys`. Не перебирать варианты.
- После смены тарифа или перезагрузки сервера отпечаток хоста и вход проверяются заново.
- Raw-вывод SSH с адресом в состояние не писать.

**PASS:** все три проверки A, B, C пройдены, каждая со своим доказательством; отпечаток хоста сверен независимо. Записывать тремя вызовами: `-Accept 4 -Source key-created+key-installed+key-login -Evidence L` только после всех трёх; промежуточные факты — в `state/state-card.md`.

**Ошибка:** ветка SSH (см. `procedures/ssh-troubleshooting.md`), записать, какая из проверок A/B/C не прошла и число попыток.

Статус референса: key-only вход для root и обычного пользователя подтверждён на одном контуре. Независимого прогона другим человеком нет `[?]`.

# Туннели: необязательный модуль

Туннель связывает сервер и ваш компьютер через уже работающее исходящее SSH-соединение. Это не даёт серверу другую географию, доступ к AI-сервисам или работу 24/7: компьютер засыпает, выключается, меняет сеть, и связь рвётся. Публичный IP компьютера, проброс портов роутера и локальный SSH-сервер для этого не нужны. Второй VPS для первого опыта не покупается.

## Сначала назначение (одно из)
1. Доступ к приложению сервера с компьютера — **локальный проброс** (`ssh -L`).
2. Сервер обращается к сервису на компьютере — **обратный проброс** (`ssh -R`).
3. Выход отдельных запросов сервера через другой узел — нужен локальный прокси с обратным туннелем; проверяется **реальный внешний адрес целевого запроса с сервера**, DNS и поддержка proxy нужным клиентом. Проверка «страница открылась» этого не доказывает. Весь трафик по умолчанию не направляется, открытый публичный proxy не создаётся.
4. Постоянная приватная сеть из нескольких узлов — WireGuard или готовая overlay-сеть по актуальной документации (учесть NAT, ОС, существующий VPN, внешний control plane, цену и права). Собственный протокол VPN не разрабатывается.

## Временная лабораторная проверка (A/B)
`bash procedures/tunnel-lab.sh <алиас-ssh-хоста>` (нужен вход по ключу; пароль не запрашивается):
- **A** — тестовый сервис на loopback сервера → `ssh -L` → loopback компьютера; проверяется уникальная метка.
- **B** — тестовый сервис на loopback компьютера → `ssh -R` → loopback сервера; метку запрашивает сервер.
- До начала: занятость портов с обеих сторон и актуальный доступ (старый успешный вход гарантией не считается).
- Только loopback, без `GatewayPorts`, без публичного порта, без изменений SSH и файрвола, без установки пакетов, без автозапуска.
- После: останавливаются **только** созданные процессы (не все `ssh`), удаляется одна временная папка, проверяются закрытые порты и сохранность основного доступа.
- Диагностика различает: порт занят (`PRECHECK FAIL`), форвардинг отказан или соединение оборвалось (`FORWARD_PROCESS_ENDED`), сервис остановлен (`TEST_SERVICE_NOT_RUNNING`), сеть недоступна (`NETWORK_OR_ACCESS_DOWN`), путь туннеля (`TUNNEL_PATH_PROBLEM`). Если сервер запрещает форвардинг, эффективные настройки выясняются, но автоматически не меняются и с общим hardening не совмещаются.

## Приёмка
- Оба направления передали метку своего сервиса.
- Новых слушающих сокетов на не-loopback интерфейсах нет (`PUBLIC_LISTENERS PASS`).
- Основной SSH и VPN работают после теста (`MAIN_SSH PASS`); всё созданное убрано (`CLEANUP PASS`).
- Внешний выход фиксируется **отдельно**: его нельзя вывести из PASS обычного туннеля. Работа 24/7, маршрут между двумя серверами, география AI-сервисов и доступ из сети провайдера участника этой проверкой не подтверждаются.

## Постоянный режим
Отдельная задача с планом и откатом: управление процессом (служба, автоперезапуск), аутентификация, поведение при сне и перезагрузке. Временный тест автозапуска не создаёт.

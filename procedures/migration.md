# Перенос приложения и диагностика Telegram после переноса

Работающий VPS не переносится ради прохождения маршрута. Поддерживаются три случая: **существующий сервер**, **новый сервер**, **гибрид**. Свой путь называется до начала.

## До переноса: оценка
Реальная задача 24/7; свободное место и память; объём данных; базы; среда выполнения; фоновые службы; внешние зависимости; домен и callback/webhook. Если проект не помещается в диск целевого сервера (пример: 60 GB данных при 40 GB диска), решение — уменьшить переносимый объём, другой диск или другой сервер, а не «копировать как есть». Кеши и воспроизводимые зависимости отделяются от важных данных. Весь ноутбук по умолчанию не копируется. Внешняя резервная копия не должна исчезать вместе с неоплаченным VPS.

## Порядок
1. Инвентаризация (что, где, сколько, чьи права).
2. Резервная копия **с проверкой восстановления** (копирование папки работоспособность не доказывает).
3. Развёртывание в отдельном месте.
4. Проверка базы и служб.
5. Проверка интеграций (раздел ниже).
6. Согласованное переключение.
7. Сохранение отката.
Токены и пароли в отчёт не попадают; владелец и права хранилища секретов сохраняются. При смене домена проверяются DNS, TLS, callback/webhook и права на домен.

## Telegram не работает после переноса: порядок проверок
Ни географией провайдера, ни Windows, ни «кривым переносом» причина не объявляется без доказательств. Одна проверка за шаг, результат записывается (`-Attempt MIGRATION ...`).
1. **DNS** — имя API Telegram разрешается с сервера.
2. **TCP/HTTPS/TLS** — соединение с портом 443 и рукопожатие проходят.
3. **IPv4/IPv6** — оба семейства адресов; проблема только в одном из них — отдельный диагноз.
4. **Маршрут/proxy** — какой маршрут и proxy реально использует процесс приложения (а не оболочка).
5. **Настройки приложения** — режим бота: webhook или polling; адрес webhook; согласованность токена и бота.
6. **Секрет** — доступен в нужной учётной записи и службе (владелец и права), значение не выводится.
7. **Единственный получатель** — не запускать двух конкурирующих получателей обновлений при тестах.
Разрешённый read-only запрос к API (например, проверка бота) **не** доказывает работу всей интеграции: тестовое сообщение отправляется только после согласования. Аналогия с проблемой публикации на другом компьютере — гипотеза, а не диагноз чужого сервера.

## Остановка кругов
Те же правила 21–22: две безрезультатные попытки в области `MIGRATION` останавливают круг; следующий шаг — конкретное изменение условий или обращение по `templates/support-request.md`.

# Проверки этапа 11 (Ports) и этапа 12 (reconnect)

Перед этапом 11 агент сверяет, что `demo/workshop-demo/*` совпадает с `demo/SOURCE-HASHES.md` (источник: `MANIFEST.sha256`). Каждая проверка записывается отдельно с исполнителем и меткой (`L` проверено агентом, `U` — человеком). Не сливать с QA кода.

## Этап 11
| № | Проверка | Кто / место | Метка |
|---|---|---|---|
| 11.1 | Приложение запущено, процесс виден | `AGENT` (сервер) | L |
| 11.2 | Порт слушает только loopback: в выводе `ss -ltn` адрес `127.0.0.1:<порт>`, нет `0.0.0.0:<порт>` и `[::]:<порт>` | `AGENT` | L |
| 11.3 | Файрвол не менялся: правил для `<порт>` нет (`ufw status`) | `AGENT` | L |
| 11.4 | Вкладка Ports в VS Code показывает проброшенный порт; адрес открыт в браузере ноутбука | `HUMAN` | U |
| 11.5 | «Начать проверку» → добавить две новые задачи → приложение показывает шаг 2 | `HUMAN` | U |
| 11.6 | Отметить одну из двух задач выполненной → приложение показывает шаг 3 | `HUMAN` | U |
| 11.7 | Обновить страницу (F5) → задачи и отметка на месте (`localStorage` браузера) → приложение показывает шаг 4 | `HUMAN` | U |
| 11.8 | Удалить выполненную задачу, оставив вторую → появился экран завершения | `HUMAN` | U |

Границы: 11.7 доказывает хранение в браузере, а не на VPS. Экран завершения — событие приложения: он закрывает только факт `APP_BROWSER` и не заменяет безопасность, переподключение, QA или итог маршрута. Сообщение, которое человек приносит с экрана, — слова человека (`U`); агент сверяет состояние сам.
